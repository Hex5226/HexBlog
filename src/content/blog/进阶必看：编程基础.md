本篇面向**刚接触编程**的新手，通篇通俗易懂，仅涉及**常识和广泛共识**，  
无特定编程语言或专业方向限制，用于打好基础，加深对计算机的理解，  
适合大学需要上计算机课程，但对此一窍不通的人群

## 编程到底是什么

人与人之间需要沟通传递信息，计算机亦是如此  

机器可不会读心，人与机器交流也需要一个途径  

**编程**就是**人与机器沟通的过程**  

你为计算机**下达指令**，它让你的**想法实现**

## 计算机的母语：二进制
既然编程是人与机器的沟通，那一个合适的**语言**必不可少

计算机内部的一切，最终都归结为**两种状态**：开和关，通和断，高电平和低电平

这两种状态用数字表示就是 **0** 和 **1**

这就是二进制

所有数据，不管是一张图片、一段音乐、一篇文档，还是你正在玩的游戏，在计算机眼里都是一长串 0 和 1

比如字母 `A` 在计算机里存成 `01000001`

数字 65 也是 `01000001`

它们用的是同一套编码规则，所以才会有“字符编码”这个概念（比如 ASCII 码）

### 为什么是二进制而不是十进制

计算机用二进制，根本原因在于**物理实现容易**

电路只有两种**稳定状态**——通电和断电，对应 1 和 0

如果用十进制，就得设计**十种稳定状态**的电路，那**成本**高得离谱，**可靠性**也差

所以二进制不是“选择”，是“只能这样”

### 二进制不够直观，于是有了十六进制

二进制写出来**太长了**

比如十进制 255 写成二进制是 `11111111`，看着还行，但再大一点呢

`1111111111111111` 是 65535

这已经很难一眼看出是多少了

所以程序员发明了十六进制——用 0-9 和 A-F 共 16 个符号表示数值

一位十六进制正好对应四位二进制

`FF` 就是 `11111111`，`FFFF` 就是 `1111111111111111`

简洁很多，而且转换方便


## 机器码：计算机真正执行的指令

二进制数据中，有一部分是**指令**——告诉 CPU 要做什么

比如“把这两个数相加”“把结果存到内存的某个位置”

这些指令的二进制形式就叫**机器码**

机器码长什么样

```asm
10110000 01100001
```

这是给 CPU 的指令，意思大概是“把 97（十进制）存入寄存器 A”  

不同 CPU 的机器码不一样——Intel 的 CPU 和 ARM 的 CPU 认得的是两套完全不同的指令  

这也是为什么**手机（ARM）**不能直接运行**电脑（x86）**上的程序

## 汇编语言：机器码的“英文翻译”

机器码全是 0 和 1，人根本没法看  

于是人们发明了**汇编语言**(Assembly Language)

汇编语言用**助记符**代替机器指令的**操作码**  

通俗讲就是用**人的语言**来代替**操作码**  

以下内容摘自“百度百科”：
>为了减轻使用机器语言编程的痛苦，人们进行了一种有益的改进：用一些简洁的英文字母、符号串来替代一个特定的指令的二进制串，比如，用"ADD"代表加法，"MOV"代表数据传递等等

上面的 `10110000 01100001` 写成汇编大概是这样：
```asm
    MOV AL, 61h
```
好记一些，但本质上还是**一对一对应机器码**——写汇编的人必须清楚 CPU 的每一个寄存器、每一条指令

汇编语言的时代，写程序的人脑子里装的是“寄存器的值是多少”“内存地址怎么跳转”这些东西

和现在写程序完全是两码事

## 高级语言：汇编实在太难写了

汇编虽然比机器码好懂了那么一点点，但写起来依然让人崩溃

你想想，写一个简单的加法就要操作寄存器、管理内存地址

写个几百行的程序，能把自己绕晕

而且汇编**绑死 CPU**——给 Intel 写的汇编，在 ARM 上跑不了

换个 CPU 就得重写，这在当年简直是噩梦

于是人们想要一个更**像人话**的编程方式

1950 年代开始，各种**高级语言**陆续诞生

最早有 FORTRAN（搞科学计算的），后来有 COBOL（搞商业的）

但这些离我们都太远了，我更想聊的是 C 语言

C 语言在 1972 年诞生，它的特别之处在于：它既有高级语言的**可读性**，又保留了汇编的**底层控制力**

比如你想让计算机算 3+5，只需要写一行接近人话的指令——"定义一个叫 a 的变量，把 3+5 的结果存进去"——编译器会帮你翻译成机器码

但你仍然可以直接操作内存、管理指针（指针就是记录数据放在内存哪个位置的号码牌），做汇编能做的事

所以 C 语言被称为"高级汇编"，也被称为"中级语言"

它是很多现代操作系统（包括 Windows、Linux）的内核语言

学了 C 语言，你会对计算机的内存管理、指针、地址这些概念有直观的感受

这也是为什么很多大学的计算机专业，第一门语言就是 C

## 编译器：把人类语言翻译成机器语言

前面提到了编译器，它到底是什么

简单说，编译器就是**翻译器**

它把程序员写的源代码（人类可读），翻译成机器码（CPU 可执行）

这个翻译过程不是简单的一步到位，而是分了好几个阶段

### 第一阶段：词法分析

编译器从左到右扫描源代码，把一个个字符拼成有意义的**单词**（叫 Token）

比如你写了

```
int age = 25;
```

这行代码用人话翻译就是：**创建一个叫 age 的容器，往里面放数字 25**

编译器拿到这行后会把它切成五个零件：`int`（关键字，表示"整数类型"）`age`（标识符，就是变量名）`=`（运算符）`25`（数字）`;`（分隔符，表示这句话说完了）

它不管这些零件是干嘛的，只管把它们切分出来

### 第二阶段：语法分析

切好单词之后，编译器检查这些单词**组合在一起是否合法**

按照语言的语法规则，构建一棵**语法树**

`int age = 25` 的语法树大概是：声明语句 → 类型 int → 变量名 age → 初始化表达式 → 值 25

如果你写成 `int 25 = age`，语法分析阶段就会报错——因为这不合法

### 第三阶段：语义分析

语法对了，还要检查**逻辑合不合理**

比如你把一个字符串赋值给一个整型变量

语法上可能没问题，但类型不匹配

语义分析就会检查这类问题

### 第四阶段：中间代码生成

前三步处理完之后，编译器生成一种**中间表示**（IR）

它既不是源代码，也不是机器码，而是介于两者之间

用中间代码的好处是：同一个 IR 可以生成不同 CPU 的机器码

这样编译器就能比较容易地支持多种平台

### 第五阶段：优化

编译器会尝试优化你的代码

比如你把 `3 + 5` 直接写在代码里，编译器可能直接帮你算成 `8`，省去运行时计算

又比如某个变量你定义了但从没用过，编译器可能会把它删掉

### 第六阶段：代码生成

最后一步，把中间代码转换成目标 CPU 的机器码

到这里，一个 `.c` 文件就变成了 `.exe`（Windows）或者可执行文件（Linux）

这就是编译的全过程

听起来步骤很多，但现代编译器跑得飞快，几百行的代码眨眼就编译完了

### 解释器：不需要编译也能跑

编译有一个缺点：**改了代码就要重新编译**

调试的时候改一行、编译一次、运行一次——来回折腾很慢

于是有了解释器

**解释器**不生成可执行文件，而是**边读边执行**

你写一行，它执行一行

Python 和 JavaScript 就是典型的解释型语言

好处是写代码直接跑，反馈特别快，调试也方便

坏处是运行速度通常比编译型语言慢

因为解释器要在运行时逐行翻译，没法像编译器那样提前做全局优化

### 中间路线：字节码 + 虚拟机

还有一种折中方案

Java 和 C# 走的就是这条路

它们先把源代码**编译**成**字节码**（不是机器码，是一种中间形式）

然后由**虚拟机**来执行字节码

虚拟机可以理解为一个"假 CPU"，它在真实 CPU 上模拟执行字节码

这样做的好处是：一次编译，到处运行

你在 Windows 上编译出来的 Java 字节码，可以在 Linux、macOS 上直接跑

只要目标机器装了对应的虚拟机就行

现代 Java 的虚拟机还会在运行时做 **JIT 编译**（Just-In-Time，即时编译）

把热点代码（频繁执行的代码）动态编译成机器码，速度和编译型语言差不太多

## 编程语言的分类，其实没那么绝对

很多人喜欢把语言分成"编译型"和"解释型"

但这两者之间的界限越来越模糊了

下面这张表是传统的粗略分类，帮你建立一个大方向上的认知

| 语言 | 传统分类 | 实际情况 |
|------|----------|----------|
| C / C++ / Rust / Go | 编译型 | 直接编译为机器码，执行效率最高 |
| Python / Ruby / JavaScript | 解释型 | 传统上是解释执行，但现代引擎也用了大量编译优化 |
| Java / C# / Kotlin | 混合型 | 编译为字节码，再由虚拟机执行（含 JIT） |
| TypeScript | 转译型 | 编译为 JavaScript 后再运行，可以理解为"翻译成另一种高级语言" |

JavaScript 的 V8 引擎（Chrome 浏览器用的）就是一个典型例子

它既有解释器快速启动，又有 JIT 编译器优化热点代码

所以你没法简单地说 JavaScript 就是解释型语言

这些分类只是帮助你建立大局观

具体到每个语言，最好自己去了解它实际的执行方式

## 操作系统：你的程序不是孤岛

写一个程序，不是凭空跑的

它需要**操作系统**来提供运行环境

我写的代码想要在屏幕上显示"Hello World"这几个字，不是直接发给 CPU 就能做到的

是操作系统帮我接管了这个请求，安排 GPU 渲染文字，通知显示器输出

程序想读取硬盘上的文件，也不是自己去读扇区

是操作系统提供了**文件系统**这个抽象层，你只要调用打开文件的函数就行

操作系统还负责**内存管理**

每个程序以为自己独占一整块内存，其实那是操作系统给你分配的**虚拟内存**

真实物理内存被切成小块，分配给不同程序

程序 A 碰不到程序 B 的内存

这样做既能**隔离保护**（一个程序崩溃不影响其他），又能高效利用内存（不用的内存可以临时换到硬盘上，叫"交换"）

还有**进程管理**——操作系统负责调度 CPU 时间片

你感觉电脑在同时做很多事情（放歌 + 写文档 + 下载文件）

其实是 CPU 在各个任务之间快速切换，每次执行一小段时间

因为这些切换速度极快（毫秒级），你感觉就像是同时进行的

## 这些和编程有什么关系

看起来我在讲一些很底层的概念

但这些概念会直接影响你写程序的方式

比如你理解了内存管理，就知道为什么有些语言要手动释放内存（C/C++），有些语言自动回收（Python/Java）

理解了编译过程，就知道为什么 C 语言编译出来体积小跑得快，而 Python 脚本需要一个解释器

理解了操作系统进程调度，就能理解"多线程编程"到底在争什么资源

这些是**底层共识**，不管你以后去学什么语言、做什么方向

它们都会在你理解计算机的道路上帮到你

不需要死记硬背，有个印象就行，以后遇到实际问题时你能想起来
